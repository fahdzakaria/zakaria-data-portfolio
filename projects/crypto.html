Étude de cas · 2025

Suivi des prix crypto

Une ingestion de prix de cryptomonnaies en quasi temps réel, qui reste debout face aux erreurs de l'API et alimente un tableau de bord Metabase.

  • Python
  • Airflow
  • Docker
  • PostgreSQL
  • Metabase
  • API CoinGecko
Code sur GitHub README

Problème

Une API capricieuse, des données qui doivent rester à jour

Contexte

Les API crypto renvoient des erreurs intermittentes (limites de débit 429, coupures réseau). Le système doit rester opérationnel et garder les données disponibles.

Objectif

Une ingestion continue par cryptomonnaie, sans échec global, avec upsert à la minute et agrégats horaires et quotidiens pour Metabase.

Décisions techniques

Robuste par construction

Robustesse face à l'API

  • Nouvelles tentatives à délai exponentiel, plafonné.
  • Erreur isolée par cryptomonnaie : une panne n'arrête pas les autres.

Stockage analytique

  • Upsert sur (coin, timestamp) : relancer ne crée pas de doublon.
  • Vues matérialisées rafraîchies en autocommit pour permettre CONCURRENTLY.
Requête représentative
1SELECT hour, coin, avg_price, pct_change_1h
2FROM crypto.hourly
3ORDER BY hour DESC
4LIMIT 2000;

Résultat

Ce que ça change

Côté données

Pipeline tolérant aux limites de débit : récupération partielle utile et tables toujours à jour pour les cryptomonnaies disponibles.

Côté produit

Tableau de bord de comparaison entre deux dates : prix, volume, capitalisation et variation.
