Case study · 2025

Crypto price tracking

Near-real-time cryptocurrency price ingestion that keeps running through API errors and feeds a Metabase dashboard.

  • Python
  • Airflow
  • Docker
  • PostgreSQL
  • Metabase
  • CoinGecko API
Code on GitHub README

Problem

A temperamental API, data that must stay fresh

Context

Crypto APIs return intermittent errors (429 rate limits, network drops). The system must stay operational and keep the data available.

Goal

Continuous ingestion per cryptocurrency, with no global failure, minute-level upsert and hourly and daily aggregates for Metabase.

Technical decisions

Robust by design

Resilience to the API

  • Retries with capped exponential backoff.
  • Errors isolated per cryptocurrency: one failure doesn't stop the others.

Analytical storage

  • Upsert on (coin, timestamp): rerunning creates no duplicates.
  • Materialized views refreshed in autocommit to allow CONCURRENTLY.
Representative query
1SELECT hour, coin, avg_price, pct_change_1h
2FROM crypto.hourly
3ORDER BY hour DESC
4LIMIT 2000;

Result

What it changes

Data side

Pipeline tolerant of rate limits: useful partial retrieval and tables always up to date for the cryptocurrencies available.

Product side

Dashboard comparing two dates: price, volume, market cap and change.
